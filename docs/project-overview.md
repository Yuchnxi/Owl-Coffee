# Owl Coffee 项目总说明

> 项目名称：Owl Coffee  
> 后台系统名称：Owl Coffee 管理系统  
> 项目定位：真实商用项目  
> 首版目标：后台优先，完成可演示的经营闭环  
> 当前版本：v1 MVP 规划  

---

## 1. 项目概述

Owl Coffee 是一套面向咖啡门店经营的完整数字化项目，包含后台系统、官网、小程序和服务端。

项目首版围绕单店经营场景设计，优先完成后台管理能力，并逐步补齐小程序点单和官网品牌展示。整体视觉以 Owl Coffee 品牌为核心，延续暗色咖啡馆氛围、咖啡橙主色、猫头鹰咖啡师 IP 和专业后台体验。

当前项目已有后台 UI 设计规范、Logo、登录页、仪表盘、订单列表和订单弹窗等视觉素材，可作为后台系统开发的主要设计依据。

---

## 2. 项目目标

首版目标是完成一套可演示、可扩展的 Owl Coffee 经营系统。

核心目标：

1. 建立统一的品牌和产品方向。
2. 完成后台系统核心经营管理能力。
3. 支持小程序用户到店自提点单流程。
4. 搭建官网品牌展示入口。
5. 建立服务端接口基础，为后续真实商用扩展预留空间。

首版成功标准以“可演示闭环”为主，即能够从后台维护商品，到小程序下单，再到后台处理订单，形成完整业务流程。

---

## 3. 产品范围

项目包含以下四个部分：

| 产品 | 首版定位 | 说明 |
|---|---|---|
| 后台系统 | 经营管理核心 | 管理商品、订单、用户、库存、营销和系统配置 |
| 小程序 | 用户点单入口 | 支持商品浏览、购物车、下单、订单查看和到店自提 |
| 官网 | 品牌展示入口 | 展示品牌、菜单、门店和联系方式 |
| 服务端 | 数据与接口支撑 | 提供后台、小程序、官网所需接口和业务逻辑 |

首版不包含：

- 多门店经营
- 加盟商管理
- 多层组织权限
- 真实微信支付
- 官网在线交易
- 复杂财务结算
- 第三方配送对接

---

## 4. 三端说明

### 4.1 后台系统

后台系统是首版优先建设的核心端，用于门店日常经营管理。

主要职责：

- 管理商品和分类
- 查看经营数据
- 处理用户订单
- 管理用户信息
- 查看库存预警
- 配置营销活动
- 管理后台角色和权限
- 维护基础系统配置

后台视觉和交互必须遵循 `docs/ui-design-system.md`。

### 4.2 小程序

小程序是用户点单入口，首版以到店自提为核心流程。

主要职责：

- 浏览咖啡商品
- 查看商品详情
- 加入购物车
- 提交订单
- 模拟支付
- 查看订单状态
- 展示取餐信息

首版支付使用模拟支付，不接入真实微信支付。后续商用版本预留微信支付接入能力。

### 4.3 官网

官网是 Owl Coffee 的品牌展示入口，首版不承担在线交易。

首版页面：

- 首页
- 品牌介绍
- 咖啡菜单
- 门店信息
- 联系我们

官网内容以品牌感、门店氛围和产品展示为主，视觉风格应与 Owl Coffee 品牌体系一致，但不需要完全复制后台暗色管理界面。

### 4.4 服务端

服务端为后台系统、小程序和官网提供统一接口。

主要职责：

- 登录和权限校验
- 商品数据管理
- 订单数据管理
- 用户数据管理
- 库存数据管理
- 营销数据管理
- 系统配置管理
- 基础日志记录

## 5. 首版 MVP 范围

首版采用后台优先策略。

### 5.1 后台首版模块

| 模块 | 首版能力 |
|---|---|
| 登录 | 管理员和店员登录 |
| 仪表盘 | 展示销售额、订单数、待处理订单、库存预警等核心数据 |
| 商品管理 | 一级菜单，下设商品列表、商品分类和库存管理；支持商品新增、编辑、上下架、删除、图片上传、SKU 维护和库存查看 |
| 订单管理 | 订单列表、详情、新增、编辑、状态处理 |
| 用户管理 | 用户列表、基础信息查看 |
| 库存管理 | 作为商品管理二级菜单，提供库存列表、库存预警 |
| 营销管理 | 基础活动或优惠配置 |
| 系统设置 | 基础门店和系统配置，包含账号管理和角色权限 |

### 5.2 小程序首版模块

| 模块 | 首版能力 |
|---|---|
| 首页 | 展示品牌、推荐商品和快捷入口 |
| 商品列表 | 按分类浏览商品 |
| 商品详情 | 查看商品图、价格、规格和说明 |
| 购物车 | 管理已选商品 |
| 提交订单 | 选择到店自提并提交订单 |
| 支付结果 | 展示模拟支付结果 |
| 订单列表 | 查看历史订单 |
| 订单详情 | 查看订单状态和取餐信息 |
| 我的 | 展示用户基础信息 |

### 5.3 官网首版页面

| 页面 | 首版内容 |
|---|---|
| 首页 | 品牌主视觉、推荐咖啡、门店亮点 |
| 品牌介绍 | 品牌故事、猫头鹰咖啡师 IP 说明 |
| 咖啡菜单 | 产品分类和代表商品展示 |
| 门店信息 | 门店地址、营业时间、联系方式 |
| 联系我们 | 联系方式、留言入口或地图信息 |

## 6. 用户角色

首版后台角色分为管理员和店员。

| 角色 | 职责 |
|---|---|
| 管理员 | 管理商品、订单、用户、库存、营销、权限和系统设置 |
| 店员 | 处理订单、查看商品和库存、完成日常门店操作 |

小程序用户为普通消费者，主要完成浏览、点单、下单和查看订单。

---

## 7. 核心业务流程

### 7.1 商品维护流程

```txt
管理员登录后台
→ 新增或编辑商品
→ 设置价格、分类、库存和上下架状态
→ 小程序展示可售商品
```

### 7.2 用户点单流程

```txt
用户进入小程序
→ 浏览商品
→ 加入购物车
→ 提交到店自提订单
→ 模拟支付成功
→ 生成订单和取餐信息
```

### 7.3 订单处理流程

```txt
后台收到新订单
→ 店员查看订单
→ 处理制作状态
→ 完成订单
→ 用户在小程序查看订单状态
```

### 7.4 官网浏览流程

```txt
访客进入官网
→ 查看品牌介绍
→ 浏览咖啡菜单
→ 查看门店信息
→ 获取联系方式
```

## 8. 技术架构

### 8.1 技术路线

| 端 | 技术栈 |
|---|---|
| 后台系统 | Vue 3 + Element Plus + JavaScript |
| 官网 | Vue 3 + Tailwind CSS |
| 小程序 | 微信原生小程序 |
| 服务端 | Node.js + Egg.js |

### 8.2 架构说明

```txt
后台系统
小程序
官网
  ↓
服务端 API
  ↓
数据库 / 文件存储 / 日志
```

首版建议优先完成服务端基础接口和后台管理端，再接入小程序点单流程，最后补齐官网展示内容。

### 8.3 支付策略

首版使用模拟支付，确保点单流程可演示。

后续真实商用版本需要补充：

- 微信支付商户号
- 支付回调接口
- 订单支付状态校验
- 退款流程
- 支付日志
- 异常订单处理机制

## 12. 首版验收标准

首版以可演示闭环为验收目标。

验收标准：

1. 后台系统可登录，并能进入仪表盘。
2. 后台可维护商品数据。
3. 小程序可展示后台维护的商品。
4. 小程序可完成到店自提下单流程。
5. 首版可完成模拟支付。
6. 后台可查看和处理小程序订单。
7. 小程序可查看订单状态。
8. 官网可展示品牌、菜单、门店和联系方式。
9. 后台视觉符合 `docs/ui-design-system.md`。
10. 项目不依赖未提供的真实商用资料即可完成演示。

## 13. 重要约束

1. 后台系统使用 JavaScript，不新增 TypeScript 文件。
2. 后台系统不使用 PageContainer。
3. 后台新增、编辑、详情优先使用弹窗。
4. 后台列表页统一为：搜索区域 → 功能按钮区域 → 表格区域 → 分页区域。
5. 官网首版只做品牌展示，不做在线交易。
6. 小程序首版只做单店到店自提，不做外送。
7. 首版不接真实微信支付。
8. 所有缺失真实资料必须标记为“待补充”，不要编造。
