# Owl Coffee 后台 UI 设计规范

本文档是后台系统页面设计和开发的强制规范。后续后台页面，尤其是管理列表页，应以“订单列表”效果图为通用布局参考，保持暗色咖啡馆管理系统风格、信息密度和操作方式一致。

## 1. 设计基调

1. 后台整体采用深色工作台风格，背景使用近黑蓝色，面板使用低透明深色。
2. 主强调色使用咖啡橙，用于主按钮、金额、当前页码、重要操作和激活态。
3. 页面应偏运营管理工具风格，重点是高密度信息、快速筛选、批量处理和清晰状态，不做营销化大卡片布局。
4. Element Plus 默认亮色样式需要覆盖为暗色主题，避免亮色背景穿透。
5. 卡片和面板圆角不超过 8px，列表页不使用大面积装饰性圆角卡片。

## 2. 后台列表页通用布局

列表页统一按以下四层结构组织，不额外添加标题卡片或说明卡片：

```txt
搜索区域
→ 操作区域
→ 表格区域
→ 分页区域
```

### 2.1 搜索区域

1. 搜索区域必须使用 `el-form` 的行内表单，即 `inline`。
2. 常见字段顺序为：编号 / 名称 / 状态 / 时间 / 其他筛选。
3. 输入框、选择器、日期选择器采用紧凑尺寸。
4. 表单 label 使用白色，确保在暗色背景下清晰可读。
5. 搜索字段之后紧跟查询按钮和重置按钮。
6. 查询按钮使用咖啡橙主按钮，重置按钮使用暗色次按钮。
7. 筛选条件较多时，右侧提供“展开 / 收起”，不要默认撑高页面。

### 2.2 操作区域

1. 操作区域位于搜索区下方，表格上方。
2. 固定基础操作为新增、编辑、删除。
3. 其他按钮按业务需要增加，例如刷新、导出、批量发货、批量完成。
4. 只有新增类按钮使用咖啡橙主按钮。
5. 编辑、删除、刷新等其他操作按钮统一使用普通暗色按钮样式，不在操作区域使用红色危险按钮。
6. 删除等危险操作通过二次确认表达风险，而不是在操作区域使用强警示按钮。
7. 新增按钮文案统一使用“新增”两个字，不写“新增账号”“新增商品”等长文案。
8. 按钮应带图标，图标优先使用 Element Plus 或项目现有图标体系。

### 2.3 表格区域

1. 表格使用暗色背景，行分隔线低对比，保持安静但可扫描。
2. 表头固定为深色半透明风格，文字略亮于正文。
3. 表格列优先展示业务关键字段，避免首版加入过多低频字段。
4. 表格列默认使用居中对齐。
5. 金额使用咖啡橙强调。
6. 状态字段使用小尺寸标签，颜色按状态语义区分。
7. 操作列固定在右侧，基础操作为编辑和删除，低频操作放入“更多”下拉。
8. 表格支持横向滚动时，操作列仍应可见。
9. 表格区域需要固定高度或使用 flex 填满 Main 剩余区域。
10. 表格中的日期时间统一格式为 `YYYY-MM-DD HH:mm:ss`，例如 `2026-06-13 00:00:00`。

### 2.4 分页区域

1. 分页位于页面底部右侧。
2. 左侧显示总数，例如“共 128 条”。
3. 右侧显示每页数量、上一页、页码、下一页和前往页码。
4. 当前页使用咖啡橙高亮。
5. 分页区域必须中文化，例如“共 128 条”“上一页”“下一页”“前往”。
6. 分页区域固定在 Main 底部，表格占据搜索区和分页之间的剩余高度。
7. 搜索区域、操作区域、表格区域和分页区域不添加功能边框。

## 3. 状态与标签

状态标签应保持短文案和固定语义：

| 类型 | 示例 | 视觉建议 |
| --- | --- | --- |
| 待处理 | 待付款、待发货、待制作 | 橙色 / 黄色 |
| 进行中 | 已发货、制作中 | 蓝色 |
| 成功完成 | 已支付、已完成 | 绿色 |
| 关闭终止 | 已关闭、已取消 | 灰色 |
| 异常退款 | 退款中、已退款 | 紫色 / 红色 |

## 4. 操作列规则

1. 操作列只展示当前状态下最常用的 2-4 个动作。
2. 状态相关动作应按业务流程排序，例如查看、编辑、发货、取消、更多。
3. 删除、关闭、退款等危险操作需要二次确认。
4. “更多”用于收纳低频动作，不要让操作列过长。
5. 操作文案使用中文短词，不使用解释性长句。

## 5. 表单与弹窗

1. 新增、编辑、详情、重置密码等操作优先使用弹窗。
2. 弹窗宽度按内容控制，常规表单建议 480px-720px。
3. 表单字段按业务顺序排列，必填项靠前。
4. 详情弹窗使用描述列表或紧凑信息块，不做大卡片堆叠。
5. 删除、禁用、关闭、退款等危险动作必须使用确认弹窗。
6. 功能页中的新增、编辑弹窗必须封装为子组件，放在当前功能目录的 `childComps/` 下。
7. 页面目录示例：`src/views/settings/admin-users/index.vue`，新增编辑弹窗示例：`src/views/settings/admin-users/childComps/AccountFormDialog.vue`。

## 6. 后台账号管理页补充要求

`系统设置 > 账号管理` 应按列表页通用布局实现：

1. 搜索区包含登录账号、姓名、手机号、角色、状态。
2. 搜索区使用 `el-form inline`，label 为白色。
3. 操作区固定提供新增、编辑、删除，其余按钮按需要增加。
4. 新增按钮文案为“新增”，并使用咖啡橙主按钮；编辑、删除等按钮使用普通暗色按钮。
5. 表格展示登录账号、姓名、手机号、角色、状态、最近登录、创建时间和操作。
6. 表格列居中对齐，末尾操作区域至少包含编辑和删除。
7. 新增、编辑弹窗封装到 `childComps/`。
8. 详情、重置密码使用弹窗。
9. 启用、禁用、删除必须二次确认。

## 7. 禁止事项

1. 禁止在后台管理页使用官网式大 hero、营销式介绍区或装饰性大图。
2. 禁止使用浅色默认 Element Plus 表格样式。
3. 禁止列表页信息过度卡片化。
4. 禁止无必要新增多层权限、按钮级权限或多组织 UI。
5. 禁止用“待补充”以外的内容编造真实门店、商品、联系方式或业务配置。
